# 序列帧识别强化与手动排除 — 设计方案

> 日期：2026-06-16
> 状态：设计已确认，待实施
> 角色：产品总监（裁决）/ Tech Lead（实现）

---

## 1. 背景与目标

部分静帧素材（如静帧变体 `..._seed_01` / `..._seed_02`）会被**误识别为序列帧**并合并显示。
用名单方式逐个登记太低效、不足以应变。本方案采用**双轨**解决：

- **轨 A（系统性根治）**：收紧判定算法，让大多数误识别从根上消失。
- **轨 B（例外救济）**：在侧边栏提供「这不是序列帧」按钮，处理算法仍漏判的残留个例。

---

## 2. 矛盾裁定（设计文档 vs 新规则）

| 项目 | 旧文档 `文件命名与组织规则.md` L1746-1759 | 新规则（本方案，已裁定） |
|------|------|------|
| 帧编号位置 | 仅"去掉末尾 `_NN`"，无位置约束 | **数字必须紧跟在 `add`/`screen`/`normal` 之后** |
| 帧编号位数 | 2 位（"不会有三位数，01-99 足够"） | 0 补位、从 `0001` 起；位数不固定 |

**裁定结论**：以新规则为准。关键判别轴 = **"数字的前一个 token 是否为混合模式"**，该轴**不依赖位数**，故新旧位数差异不影响算法正确性。

> 自验证：仓库自身的设计文档示例已印证本判别轴——
> 真序列帧 `bonus_vfx_a_screen_01`（数字紧跟 `screen`），
> 静帧变体 `main_vfx_a_add_seed_01`（数字紧跟补充名 `seed`）。

---

## 3. 轨 A：判定算法强化（系统性）

**位置**：`src-tauri/src/commands/scanning.rs:622-637`（Phase 1 候选判定）。

**现状逻辑**：stem 末尾为 `_<纯数字>` → 即视为序列帧候选（位数不限、不看数字前是什么）。

**变更后逻辑**：仅当 stem 形如 `<base>_<混合模式>_<纯数字>`
（即**剥掉末尾 `_数字` 后，新的末尾 token ∈ 混合模式集合**）时，才计入序列帧候选；
否则归入 standalone 静帧。

**SSOT**：混合模式集合提取为命名常量，置于 `helpers.rs`：

```rust
/// 序列帧判定：帧编号必须紧跟在这些混合模式 token 之后
pub(crate) const SEQUENCE_BLEND_MODES: &[&str] = &["add", "screen", "normal"];
```

将来新增混合模式只改这一处，杜绝魔法字符串散落。

**爆炸半径**：
- 仅影响 `scan_materials` 的 Phase 1（候选分类）与 Phase 3（散落组处理）。
- Prototype 扫描（`scanning.rs:845`~）若复用同一判定则一并统一；按业务规则 Prototype 不应有序列帧，实害极小。
- 大小写：判定前对 token 统一 `to_lowercase()`，与现有 base_name 小写约定一致。

**残留风险**：若存在"紧跟混合模式、且无补充名的静帧变体"（如 `..._add_01`），算法仍会误判 → 由轨 B 救济。

## 4. 轨 B：手动「非序列帧」按钮（例外救济）

**UI 位置**：素材详情侧边栏，当前以 Sequence 展示的素材的操作按钮区
（`design/界面设计.md` L1696，与「帧速率修改 / 打开工程文件」同列）。按钮文案：**非序列帧**。

**永续化（显性可读文件，已裁定）**：不复用 `.pgb1_notes.json`（隐藏点文件、与批注混在，不利手动撤回）。
改用**专用、可读、可手编辑的名簿文件**，与素材同居：

```
00_original/非序列帧.txt
```

文件内容自带说明头，每行一个基础名：

```text
# 此文件列出被手动标记为「非序列帧」的素材基础名，每行一个。
# 删除对应行并刷新，即可恢复为序列帧识别。
main_vfx_a_add_seed
bonus_vfx_b_screen
```

解析规则（防御性）：`#` 开头与空行忽略；首尾空白 trim；小写照合；UTF-8。

**扫描联动**：`scan_materials` 开头读取该名簿为 `HashSet<String>`；Phase 3 处理散落组时，
若 base_name 命中，则**不合并为序列帧**，而是把该组文件拆开按 standalone 静帧逐个展开。

**操作流程**：按钮 → 弹确认对话框 → `invoke('mark_not_sequence', { taskPath, baseName })` → 触发再扫描 → 该素材变为静帧群。
新增专用命令 `mark_not_sequence`（追加一行；文件不存在则带说明头自动生成；重复则忽略）。前端复用 rename/delete 既有「invoke + rescan」模式（`useMaterialSidebar.ts`）。

**可逆性（已裁定）**：应用内**不提供逆向按钮**，但**保证可撤回**——
名簿是自我说明型的显性文件，用户打开 `00_original/非序列帧.txt`、删除对应行、刷新即恢复。
确认对话框需提示"如需恢复，请编辑 `00_original/非序列帧.txt` 删除该行"，在边界处给足引导。

> 与早前被否决的"名单方式"的区别：那是反对用名簿做**识别主轴**；此处识别主轴是轨 A 的算法，
> 本名簿仅作手动按钮的永续化 + 撤回口，不矛盾。

## 一、根因（务必读完再动相关代码）

`MaterialInfo` 没有身份字段，前端四处拿 `path` 当唯一标识。而**两个字段单独都不唯一**：

| 字段 | 失效场景 | 后端出处 |
|------|---------|---------|
| `path` | 未规范化的 `00_original` 里序列帧平铺存放，同目录 N 个序列的 `path` 全是该目录本身 | `scanning.rs` 散落序列帧分支 |
| `name` | 静帧 `name` = 去扩展名 + 去 `_01` 后缀的基础名，`a.png` / `a.jpg` / `a_01.png` 全撞 | `scanning.rs` 独立文件分支 |

唯一身份 = `material_type + name + path` 三元组 → `materialUid()`（`src/composables/useMaterials.ts`，SSOT）。

**缩略图 bug 的具体时序**（`useFrameCache` 的 LRU key 原本只有 `folderPath:maxWidth`）：

1. 首次进树形视图 → N 个 `SequencePreview` 并发挂载，`cache.find` 全部 miss（都在 await 之前），
   各自加载各自的帧 → 显示正常，但缓存里塞进了 N 条 **key 完全相同**的记录
2. 切名称视图 → 组件重挂载，这次命中最早那条 → 全变成同一个序列
3. 切回树形 → 照样命中同一条，不恢复
4. `cache` 是模块级数组 → 只有刷新 / 重启才清空

## 三、遗留：命名债（未执行，需产品总监裁决后单独提交）

`selectedPaths` / `allPaths` / `data-path` 这些名字现在装的是**「选中标识」**而不是文件路径：

- `NormalCard` 走真实文件路径（本身唯一）
- `MaterialCard` 走 `materialUid()`

本次只在三个 composable 的接口注释里写明了语义，**没有改名**——改名要动
`MaterialsPage.vue` / `GameIntroPage.vue` 两个与本 bug 完全无关的页面共约 30 处，
会污染这次的 diff。

建议的清理方案（独立提交）：

- `useMultiSelect`：`selectedPaths` → `selectedKeys`，`allPaths` → `allKeys`
- `useRubberBandSelect`：`onSelect(paths)` → `onSelect(keys)`
- 卡片属性 `data-path` → `data-select-key`，同步四个页面的 `cardSelector` 字符串
- `useMaterialSidebar.preserveCardPosition` 的选择器同步

风险点：`cardSelector` 是字符串常量，改名后 TypeScript **不会报错**，必须逐页人工核对，
且 `preserveCardPosition` 的选择器与 `data-*` 属性名有隐式耦合。
